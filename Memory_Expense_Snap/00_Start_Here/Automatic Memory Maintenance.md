# Automatic Memory Maintenance

This vault is the living memory for Kharcha. Updating it is part of finishing meaningful work.

Ahmad should not need to separately ask: "update Obsidian."

## When To Update

Update Obsidian automatically when:

- A new feature, screen, service, repository, integration, model, route, or workflow is added.
- Existing behavior changes in a way future work must know.
- A mock flow becomes real.
- A product, design, architecture, or roadmap decision is made.
- A known gap is fixed.
- A new bug, design debt, or technical debt item is discovered.

## What To Update

Usually update:

- [[Current Snapshot]]
- the relevant note in [[04_Screens]]
- the relevant note in [[05_Features]]
- the relevant note in [[06_Code_Map]]
- the relevant phase under roadmap
- [[Decision Log]] when a decision was made
- [[Open Tasks]], [[Known Bugs]], [[Next Sprint]], or [[Backlog]] when task state changes

Update `Graph/Kharcha Project Graph.canvas` when a new major feature, screen, system, integration, or architecture concept deserves a visible node.

## When Not To Update

Do not update the vault for:

- Typo-only edits.
- Formatting-only edits.
- Tiny local refactors that do not change behavior, architecture, product scope, design rules, or future implementation context.

## Final Response Rule

When Obsidian is updated, mention the updated notes in the final response.
